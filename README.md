# AnimeDL

Десктопное приложение для поиска и скачивания аниме с русскоязычных онлайн-кинотеатров.

## Как устроено сейчас (as-is)

Архитектура — GUI-обёртка (Qt/C++) вокруг двух независимых консольных инструментов,
общение с которыми идёт через `QProcess` + JSON в stdout.

```
┌─────────────────────────┐
│   Qt6 Widgets (C++)     │  mainwindow.cpp/.ui, logwindow.cpp/.ui
│   MainWindow            │  вся логика в слотах on_*_clicked/on_*_itemClicked
└───────────┬──────────────┘
            │ QProcess, argv, stdout(JSON)/stderr, таймаут 20 сек
            ▼
┌─────────────────────────┐      ┌──────────────────────────┐
│  backend (PyInstaller)  │      │  yt-dlp (отдельный exe)  │
│  Python + anicli_api    │      │  скачивание .mp4/.m3u8   │
└───────────┬──────────────┘      └──────────────────────────┘
            │
            ▼
   anilibria / animego / animevost / dreamcast /
   sameband / yummy_anime / yummy_anime_org
   (жёстко зашитые Extractor-классы из anicli-ru)
```

### Frontend (Qt/C++)

- `main.cpp`, `mainwindow.cpp/.h/.ui` — главное окно: строка поиска, список источника
  (провайдер), список аниме, списки серий (одна / несколько), список озвучек/плееров,
  список качеств видео, поле пути сохранения, настройки SOCKS5-прокси, список
  запущенных процессов скачивания.
- `logwindow.cpp/.h/.ui` — отдельное окно с вкладками, по вкладке на каждый процесс
  `yt-dlp` (stdout/stderr в реальном времени).
- Настройки (прокси, путь скачивания) хранятся через `QSettings` (реестр/plist/ini).
- На каждое действие пользователя (поиск, выбор аниме, выбор серии, выбор источника)
  заново перезапускается `backend.exe` с полным набором аргументов и **пересчитывает
  весь путь с нуля** — состояние на стороне бэкенда не хранится (это CLI, не сервис).

### Backend (`backend/backend.py`)

Тонкая обёртка над библиотекой [anicli-ru (anicli_api)](https://github.com/vypivshiy/ani-cli-ru):
принимает аргументы командной строки (`search|episodes|sources|video_qualities|videos_urls`,
опционально `proxy <ip> <port> <user> <pass>` первым блоком) и печатает JSON-массив в stdout.

`get_extractor()` — `match/case` по имени провайдера, вручную сопоставленному с одним из
7 классов `Extractor` библиотеки anicli_api. Список провайдеров задан в двух местах
одновременно и независимо: в `comboBoxProvider` (mainwindow.ui) и в `match/case`
(backend.py) — источники нельзя добавить/убрать/настроить без пересборки обеих частей.

Собирается через PyInstaller (`--onedir`) в `backend/dist/backend/`, при сборке CMake
копирует эту директорию рядом с `animedl.exe`.

### Скачивание — yt-dlp

`yt-dlp` скачивается автоматически в CMake-скрипте (последний релиз с GitHub), запускается
как независимый `QProcess` на каждую серию, с ограничением на число параллельных
процессов (`spinBoxProcesses`) — реализовано вручную очередью групп
(`startNextGroup`/`pendingEpisodes`) в `mainwindow.cpp`. Прогресс и лог каждого процесса
уходят в `LogWindow`.

### Сборка

`CMakeLists.txt` — оркестрирует всё: собирает Qt-приложение, создаёт venv и ставит
зависимости backend'а (`bootstrap_backend.py`), пересобирает его PyInstaller'ом только
при изменении хэша исходников (`build_backend.py`), скачивает `yt-dlp`, копирует
`version.txt`. CI (`.github/workflows/build.yml`) собирает релиз только под Windows
(MinGW + `windeployqt`).

### Ограничения текущей архитектуры

- Источники (провайдеры) жёстко зашиты в коде на двух языках сразу — добавить свой
  источник или отключить сломанный без пересборки нельзя.
- Нет общего состояния сессии — каждый клик пересчитывает всю цепочку поиска заново
  через новый процесс Python.
- Смешение двух рантаймов (C++/Qt + Python/PyInstaller) усложняет сборку и упаковку
  (venv, хэш пересборки, PyInstaller, windeployqt).
- Кросс-платформенность декларативная (`Q_OS_WIN`, `#else`), но CI и релизы — только
  Windows.
- Индикация процессов скачивания хранит сырой указатель `QProcess*` в
  `QListWidgetItem::UserRole` (`quintptr`) — работает, но хрупко.
- Только SOCKS5-прокси, один общий тумблер на всё приложение.

## План: переезд на Node.js + Electron

Цель — оставить пользовательский сценарий тем же (поиск → выбор аниме → выбор серий →
выбор озвучки/источника → выбор качества → скачивание через yt-dlp, с логами и
прокси-настройками), но:

1. убрать двухъязычную архитектуру (C++/Qt + Python) в пользу единого рантайма
   Node.js/TypeScript;
2. отвязать парсинг источников от жёстко зашитого списка — сделать источники
   плагинами с единым интерфейсом, которые можно включать/выключать/добавлять из
   самого приложения (без пересборки);
3. десктоп-оболочка — **Electron** (зафиксировано): полный Node.js в main-процессе
   (не нужен отдельный sidecar-процесс для логики, как потребовалось бы в Tauri),
   IPC между main и renderer, богатая экосистема (`electron-builder`,
   `electron-store`, `electron-updater`), одинаково собирается под
   Windows/macOS/Linux — в отличие от текущего Qt-проекта, релизящегося только под
   Windows.

### Целевая архитектура

```
┌───────────────────────────────┐
│  Renderer (React/Vue/Svelte)  │  тот же набор экранов, что и сейчас
└───────────────┬────────────────┘
                │ Electron IPC (contextBridge/preload)
                ▼
┌───────────────────────────────┐
│  Main process (Node.js/TS)     │
│  - Source Registry (плагины)   │
│  - Download Manager (yt-dlp)   │
│  - Settings (electron-store)   │
└──────┬───────────────┬─────────┘
       │               │
       ▼               ▼
┌─────────────┐  ┌───────────────────┐
│ source-*    │  │ yt-dlp (бинарник /  │
│ плагины     │  │ yt-dlp-wrap/        │
│ (по одному  │  │ youtube-dl-exec)    │
│ на сайт)    │  └───────────────────┘
└─────────────┘
```

- **Source Registry** — единый интерфейс плагина источника
  (`search(query)`, `getEpisodes(animeId)`, `getSources(episodeId)`,
  `getQualities(sourceId)`), реестр загружает плагины из папки конфигурации
  пользователя (`~/.config/animedl/sources/*` или `%APPDATA%`), а не из
  захардкоженного `match/case`. Экран настроек показывает список источников с
  тумблерами вкл/выкл и возможностью добавить новый (файл плагина / URL).
- Логика поиска/эпизодов/качеств — портируется 1:1 по смыслу из `backend.py`
  (`search_anime`, `get_episodes`, `get_sources`, `get_video_qualities`,
  `get_videos_urls`), но как чистые TS-функции, без перезапуска процесса на каждый шаг.
- Скачивание — через `yt-dlp` (бинарник, как и сейчас) или `yt-dlp-wrap`/`youtube-dl-exec`
  из Node; очередь с ограничением параллельности — явный класс `DownloadQueue`, а не
  ad hoc список указателей на процессы.
- Прокси — `socks-proxy-agent`/встроенная поддержка `--proxy` в yt-dlp, тот же UX
  (SOCKS5, вкл/выкл, поля ip/port/user/pass).
- Настройки — `electron-store` вместо `QSettings`.
- Логи процессов — тот же UX (окно с вкладками по процессу), на базе `EventEmitter`
  из `DownloadManager` и React-компонента с вкладками.
